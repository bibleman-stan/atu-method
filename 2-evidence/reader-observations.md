# Reader observations — the comprehension channel

**What this is.** The only place in the program where *reading the edition* counts as evidence. Every other instrument compares our method to another method — Skousen's judgment, Marschall's criteriology, our own Hebrew edition, a gold yardstick. Those measure consistency with a comparandum. None of them involves anyone reading, so none can say whether a line lands.

This file exists because `4-process/improvement-loops.md` records Loop 6 as MISSING and because the observations were accumulating in conversation, where they decay to anecdote. **Created 2026-08-07.**

## How to record

One entry per observation. Keep them short and keep the wording as spoken — a paraphrase loses the signal. Anything is admissible: a passage that felt wrong, a line that had to be re-read, a place the eye stumbled, a rendering that worked unexpectedly well. Positive observations matter as much as negative ones; a channel that only receives complaints measures mood, not comprehension.

Each entry carries: date, who, the reference, the observation verbatim, and — separately, so it never contaminates the observation — whether any independent instrument agrees.

**Do not resolve entries by argument.** An observation is data about a reading experience; the framework cannot overrule it, only fail to explain it. If an entry conflicts with canon, that is the finding.

## What would make this a loop rather than a list

Recording is the capture half. The integration half — the part that makes it a loop — is unbuilt: nothing yet converts a cluster of observations into a rule proposal, and nothing measures whether a change actually improved the reading. The honest status is that this file closes the *first* edge of Loop 6 and leaves the return edge open, which is the same shape Loop 5 was in until 2026-08-07.
