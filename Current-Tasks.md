## Why this file is a pointer and not a list

It was always meant to die. Its own header said so: *"it is the **seed for the GitHub Project board** — when that exists, this file is retired rather than maintained alongside it."* The board went live 2026-08-09.

It then sat here anyway, drifting — 23 commits behind by 2026-08-11 — and `loop_health.py` dutifully warned about it every session. The warning was accurate and the response it invited was wrong. **Updating this file would have restored the exact defect the board was built to end:** two places to look for pending work, quietly disagreeing.

> Stan: *"the problem has been you have had lots of places to hide the pending things; if there's only one place to look, I'll be able to catch up."*

So the check inverted. Staleness here is now expected and silent; what `check_current_tasks()` reports instead is **this file growing back into a board** — checkboxes, or more than three headed sections. That is the failure worth catching.

The pre-retirement content is preserved at [`.archive/2026-08-11-retired/Current-Tasks-2026-08-11.md`](.archive/2026-08-11-retired/Current-Tasks-2026-08-11.md).
